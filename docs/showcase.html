1The gate catches a lie the API tells confidently

Ninety-seven percent confidence. Ninety-five percent grounding. Every signal a reasonable integrator would threshold on said auto-approve. The number was wrong. This is a live transcript from the first production extraction call — not a synthetic test.

Kaniefsky Transport LLC — Invoice INV-2026-0418
ACME Freight Services
Parcel 1 ...... 2 × $14.50
Parcel 2 ...... 1 × $39.99
Handling ...... 3 × $4.00
Total due: $86.86
Tax: $5.87

"recognitionScore": 0.678

Actual document value

"total_amount": $86.86

Gate verdict: HUMAN REVIEW REQUIRED. Recognition score is the only signal measuring whether the glyphs were read correctly — not whether the value came from the right region of the page. It was the only one that dissented. The agent was not permitted to sign with the wrong total.

The second finding: agentic mode

The same invoice in agentic mode — double the cost, VLM-augmented — returned the correct totals ($86.86, tax $5.87) but silently mangled the line-item table: "Parcel 1" became description "Parcel" with quantity 1. And agentic mode emits no recognitionScore at all. Paying more bought better answers and less ability to tell whether they were right.

2Crash at the worst possible moment — recover without double-sending

The plan is approved. The agent transitions to "executing." The gateway send-draft call fires. And right now — the process dies. This is what the crash-safe lifecycle was built for.

agent@no-undo: ~/no-undo
$ node agent/esign-agent-loop.mjs [agent] Starting eSign send pipeline... [agent] Creating draft folder... [agent] Draft created: folderId=fld_abc123, planToken=pln_7f3a... [agent] Plan awaiting approval. [agent] Human approved plan pln_7f3a (actor: jpka) [agent] Plan approved. Transitioning to executing... [agent] Calling gateway send-draft endpoint... [FATAL] Process killed (SIGKILL) — mid-send

The journal recorded executing before the process died. The actual gateway call may or may not have completed — the agent will never know. The dangerous window straddles the call, and the core does not model "maybe sent."

On restart: reconcile against ground truth

agent@no-undo: ~/no-undo (restart)
$ node agent/esign-agent-loop.mjs [agent] Replaying journal... [agent] Found 1 plan stuck in 'executing': pln_7f3a [agent] Reconciling against gateway folderStatus... [agent] Gateway response: fld_abc123 → status: DRAFT [agent] DRAFT → send did not happen. Plan released for retry. [agent] Audit log: no false 'executed' entry written.  

Hash-chained audit trail

Every transition is an append-only, fsync'd record. Each line carries the hash of the previous one — tampering is detectable, and replaying the journal on restart reconstructs exactly the state the system was in when it died.

19:54:29plan_createdprevHash: 0000…0000
19:54:31approvedactor: jpkaprevHash: a1b2…c3d4
19:54:33executingprevHash: c3d4…e5f6
19:55:02reconciled_draftgateway: DRAFTprevHash: e5f6…a7b8

If the gateway had returned SHARED, the fourth line would be executed — and the audit log would be equally honest about the send that did happen. The log never lies, and it never double-sends.

Architecture

Three vendors, one gate. Reversible steps run unattended. The irreversible step — sending for signature — stops at a human approval checkpoint that survives a crash without double-sending. The gate doesn't trust the API's confidence; it trusts the signal that actually measures what matters.

Why this can win Overall

Agents are being handed write access to systems where actions cannot be undone. The industry's answer is a confirmation prompt showing what the agent thinks it's doing. This project shows what happens when the agent is confidently wrong — and what happens when the process dies at the worst possible moment. The core is published on npm. The servers are shipped. This is not hypothetical.
